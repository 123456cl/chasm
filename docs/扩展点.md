# chasm 框架扩展点清单（照着加内容即可）

> 本文只列**本仓库真实存在、且实际被用过**的 API。签名都是从源码/调用点核对的，不是设计稿。
> 每条都给出"要做这件事 → 动哪里"的位置，方便照着扩。

## 0. 三层扩展，从便宜到贵

| 层 | 想加什么 | 要不要写代码 | 热重载 |
|---|---|---|---|
| 内容层 | 材料、模块、原理图、蓝图、宝石、语言、贴图 | **不用**，扔 JSON/PNG 进数据包或资源包 | 是（`/reload`） |
| 注册层 | 新物品/方块/界面/属性/效果/附魔/伤害类型 | 几十行声明 | 否（启动期） |
| 行为层 | 新的物品行为、贡献管线、事件、SPI 扩展点 | 实现接口/回填 | 否 |

## 1. 内容层：加数据不用改代码

- **加载一个数据目录**：`api.chasm.data.ChasmContent.of(modId, dir).parse(解析器).target(落点).onRemove(注销).register()`。
  单文件解析失败**只跳过那一个文件**并告警，不会连带整批；删文件会触发 `onRemove`，注册表里不留幽灵。
- **要"按 id 查"而不是"塞进自定义 hash 表"**：用 `api.chasm.data.ChasmDataRegistry`，
  一行接管一个目录：`ChasmDataRegistry.<T>create("名字").load(modId, dir, 解析器)`；
  提供 `get/find/findByPath/find(String)/all()`（只读快照，重载自动换新）与 `addListener(Runnable)`（只做标脏）。
  参考用法：`tetra-port/.../TetraMaterials.java`（70 材料）、`TetraModules.java`（78 模块）。
- **Tetra 侧的真实数据规模**（可直接扩）：`data/tetra/materials/**` 70、`modules/**` 78、
  `improvements/**` 147、`tiers/`、`stat_bars/**` 17；`assets/tetra/lang/**` 是真语言键来源。

## 2. 注册层：声明式，不碰注册表 API

- `@ChasmMod(id = "mymod")` 标记入口类；`@Register("mana_sword")` 标在**静态字段**上，
  注册目标按字段类型路由（Item → 物品表、Block → 方块表…）。见 `api.chasm.registry.Register`、`ChasmRegistrar`。
- 物品：`Chasm.item().maxStackSize(1).durability(300).name("模块化剑").texture("minecraft:item/iron_sword").register()`。
  **自带模型**用 `.ownModel()`（此时 DataGen 不再生成占位模型，避免同路径资源重复导致构建失败）。
- 方块：`Chasm.block().name().texture().strength(hardness, resistance).requiresPickaxe().onUse(ctx -> …)`。
- 界面：`Chasm.gui(modId, name).title().panelSize(w,h).slotPx(x,y,filter,visibility).playerInventoryAt(x,y).playerInvSpacing(17).hotbarAt(y).data(key,默认,min,max).source(节点函数).nodeAction(id, handler).register()`。
- 属性/附魔/伤害类型/合成：`ChasmAttributes`、`ChasmEnchantments`、`ChasmDamageTypes`、`Chasm.recipe(...)`（`recipe.RecipeDeclaration`）。
- DataGen：`api.chasm.datagen.ChasmDataGen.generate(generator, 你的入口类.class)` 自动生成模型/语言/配方；JSON 覆写用它的覆写注册表。

## 3. 行为层：真正的"深度扩展"在这里

- **贡献管线**（物品属性/事件/耐久等横切行为）：
  `api.chasm.contrib.ChasmContributors` 注册 `ItemContributor`；给具体物品挂上用 `api.chasm.contrib.ItemContributions.attach(stack, 贡献器ID)`。
  Tetra 就是这么做的：`tetra-port/.../ModularItemContributor.java` —— 模块化属性、附魔、耐久全部挂在数据组件 + 贡献器上，
  与原版物品类**零耦合**（所以原版剑也能装模块）。
- **物品行为钩子**：`api.chasm.item.ChasmItemBehavior` 有 `destroySpeed`、`isCorrectToolForDrops`、
  `handlesMining`、`onMineBlock`、`tooltipLines`/`TooltipSlot`、`transformsVanillaTooltip` —— 自定义工具只需填这些，
  不用继承原版工具类。
- **事件层**：`api.chasm.item.event.ChasmItemEvents` + `ItemEventHandler`/`ItemEventKey`，
  载荷类型见 `item/event/payload/**`（伤害、命中、破坏方块、使用、投掷、射箭、盾挡、耐久损失…）。
  适配器 `ChasmItemHookAdapters.registerAdapter(...)` 可把外部事件源接进来。
- **Trait / 模板**：`trait.ChasmTraits`（使用/攻击/背包 tick）、`template.ChasmTemplates`（武器/食物/护甲套装/击杀奖励）。
- **状态机**：`api.chasm.state.StateMachine`（方块实体等复杂状态）。
- **工具动作**：`api.chasm.tool.ChasmToolActions.get("cut")` —— 开放字符串驻留表，
  **任何动作名都能用**（数据里 `tools` 键就是动作名），不需要在框架里先声明。
- **扩展点机制（SPI）**：`api.chasm.spi.Spis` / `MethodPoint` / `MethodFn` / `MethodPost`
  —— 让别人在**不修改你的类**的前提下替换/包装某个方法（日志里的 `SPI 扩展 mana_sword` 就是它）。
- **宝石/镶嵌**：`api.chasm.contrib.socket.ChasmGems`、`ChasmSockets`、`GemPurity`、`TieredValues`（含单元测试）。

## 4. UI 层：`ui = f(state)`

- 一个界面 = **一个节点列表函数**：`source(state -> List<GuiNode>)`。不在列表里的东西**既画不出来也点不到**（存在 ≡ 可见 ≡ 可命中）。
- 节点能力：`GuiNode.of/sprite/spriteRegion/fill/slot/inventorySlot`，链式 `.text/.action/.hover/.enabled/.delay/.behind/.opacity/.textScale/.spriteTint/.tooltip/.alphaTimeline/.slideIn`。
- 状态：`gui.data(key, 默认, min, max)` 声明的整数键（自动同步双端）；节点动作在服务端派发（`nodeAction`）。
- **坐标唯一来源**：节点几何一律走 `GuiNode.rect(menu)` 或 `DeclClient.animatedScreenRect(...)`；
  槽位几何由 `PlayerInventoryLayout`/`ChasmStorageSlot` 提供 —— 不要在别处再算一遍（历史上"三份算法"导致过整体错位）。
- **界面数据出错不崩客户端**：`DeclClient` 会把 `source.build` 的异常拦在界面边界内，打完整堆栈 + 这一帧渲染空列表；
  开发期想让它照旧直接崩，打开 `DeclClient.strictBuildFailures`。

## 5. 物品外观分层：多层贴图 + 染色（零 mixin）

**要做什么**：物品外观不是一张平面贴图，而是"装了什么模块、什么材料 → 叠哪几层贴图、每层什么染色"。
框架原先只会给一张平面贴图（DataGen 的 `generateFlatItem`），这一层完全缺失。真实 Tetra 的做法是
`ItemOverrides` + 每层贴图数据：`_ref/Tetra-1.20/tetra-1.20/src/main/java/se/mickelus/tetra/client/model/ModularOverrideList.java:42,75,92-145`、
`_ref/.../module/model/GridTextureModelData.java:26-71`（层 = 贴图 + tint + 发光 + 变换）。

### 模组侧怎么写（三行）

```java
ChasmItemLayers.register(MY_SWORD, stack -> List.of(   // 按栈求值；永不抛异常、永不返回 null
    new ItemLayer(bladeTexture, 0xFFB87333),           // ARGB；0xFFFFFFFF = 不染色
    ItemLayer.of(hiltTexture)));                       // 不染色的一层
```

- `api.chasm.model.ItemLayer(ResourceLocation texture, int tint)`：一层 = 一张贴图 + 一个 ARGB 染色。
  **染色是标准 ARGB（0xAARRGGBB），不要再交换 R/B**：Tetra 的交换是为 Forge 直接写顶点缓冲准备的
  （`_ref/.../client/model/ColorQuadTransformer.java:14-17`）；这里走原版 `ItemColors`，打包由
  `VertexConsumer.putBulkData` 完成（反汇编第 239-328 行：`FastColor.ARGB32.color(alpha, red, green, blue)`）。
  alpha 位为 0 视为不透明（同 `ColorQuadTransformer.java:10-12`）。
- `ChasmItemLayers.register(item, provider)`：重复注册以最后一次为准；第一次注册会懒挂上客户端模型插件
  （`EnvType.CLIENT` 判断在方法第一句，专用服务器不加载客户端类）。
  **provider 要在首次资源加载前注册**（正常模组初始化都在这个窗口内）；晚注册的物品要等一次资源重载
  （F3+T / `/reload`）才换上分层模型。
- 几何来源：叠层只换贴图与染色，**几何、手持/物品栏变换、渲染类型全部沿用原模型**。
  原模型没有几何时（模型 JSON 只写 `"parent": "item/generated"` 却没写 `textures` —— 原版
  `ItemModelGenerator` 会产不出元素，物品画成"什么都没有"）框架会借 `minecraft:item/paper` 的平面几何
  兜底，所以**不做任何声明也能出外观**；想控制厚度/变换就照常声明 `.texture(...)`（DataGen 生成的平面模型
  就是几何模板）。
- DataGen **不用改**：它生成的平面模型正是几何模板，两者不冲突（分层只改渲染时的 quad，不写任何文件）。

### 按栈切换怎么实现（为什么必须走 `ItemOverrides`）

provider 按**栈**求值、baked model 按**物品**烘焙，1.21.1 唯一的桥是 `ItemOverrides`：
`ItemRenderer.getModel` 先 `ItemModelShaper.getItemModel(stack)`，再
`model.getOverrides().resolve(model, stack, level, entity, seed)`（反汇编 `ItemRenderer#getModel` 第 518-538 行）。
框架在 `modifyModelAfterBake` 里只包装"注册过 provider 的物品模型"：`ctx.topLevelId()` 是
`ModelResourceLocation` 且 variant = `inventory` 时，`id()` 就是物品注册 id
（`ModelBakery.loadItemModelAndDependencies` 反汇编第 314-331 行）→ O(1) 查注册表。包装模型只重写
`getOverrides()`；几何拿原模型自己的 quad 当模板（手持/物品栏变换、渲染类型全部保持原样），换贴图时把
UV 从原贴图区域重映射（`FaceBakery` 烘焙出来的 UV 已经是图集空间）。
染色走 **tint index**：第 i 层 = `1000 + i`，颜色由注册的颜色提供者按 `ItemColors.getColor(stack, tintIndex)`
还原 —— 原版物品渲染会**丢弃** quad 顶点色（`renderQuadList` 调 8 参数 `putBulkData`，内部固定
`readExistingColor = false`，反汇编第 121-169、296-319 行），所以染色只能这么表达。

### 兼容底线 / 复杂度 / 失效

- **没注册 provider 的物品行为完全不变**：`providerOf` 返回 null、`layersOf` 返回空表，烘焙钩子原样返回
  **同一个模型实例**（连包装对象都不建）；本物品低于 1000 的 tint index 一律返回 -1（白色），
  等价于"没注册过颜色提供者"。
- 复杂度：查表 O(1)（键 = 数据组件内容哈希 `stack.getComponents().hashCode()`，零分配），每物品一张表；
  建模型只在 miss 时发生（O(层数 × 模板 quad 数)）；没有全表扫描，每帧不新建 quad/集合。
- 失效：资源重载会整批重烘焙（缓存随包装模型一起重建）；只改数据不重载的自定义链路调
  `ChasmItemLayerModels.invalidateCaches()`。单物品表上限 512 条，超了整表清空。
- 兜底：provider 抛异常/返回 null、层里带 null 贴图、贴图集取不到 sprite、模板没有几何 —— 一律退回
  原来的单张贴图并告警一次，绝不 NPE、绝不让渲染线程崩。

## 6. 目前**还不能**算扩展点的地方（诚实清单）

- 版本号固定 `1.1.2`：Loom 的 remap 缓存按"模块+版本"命中，改代码后**必须刷新**（跑 `refresh-dev.ps1`），
  否则游戏里还是旧代码 —— 这是工具链限制，不是框架能力。
- 音效/粒子/结构生成还没有统一声明入口（多方块与结构在真实数据里有，框架侧待补）。
- 客户端渲染扩展（自定义 BakedModel/渲染层）目前只有 `blockentity.client.ChasmBlockEntityRenderers` 与贴图节点，
  分层物品模型（Tetra 的模块化外观）还没做。
